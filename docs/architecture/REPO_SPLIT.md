# Splitting into three repositories

How this repository becomes **RCHENLAB/AiScientist** (the platform), **RCHENLAB/AiScientist-tools**
and **RCHENLAB/AiScientist-skills**, and how to merge the preparation branch while the tools keep
changing on main. 中文版: [REPO_SPLIT.zh-CN.md](REPO_SPLIT.zh-CN.md). Architecture overview:
[README.md](README.md).

## The target

| Repository | Holds | The platform consumes it as |
|---|---|---|
| RCHENLAB/AiScientist | `gateway/`, `agents/`, `reporting/`, `hpc/`, `core/`, `frontend/`, `deploy/`, `docs/`, platform and contract tests | (itself) |
| RCHENLAB/AiScientist-tools | `src/bioagent/tools/` (one folder per tool, `sdk.py`, `catalog.py`, `api.py`, `_lib/`, reference data, job entry points), the tool tests, `scripts/tool_docs.py` | the Python distribution `aiscientist-tools`, pinned to a tag; import path still `bioagent.tools` |
| RCHENLAB/AiScientist-skills | `skills/`, `pipelines/` (today `preset_pipelines/`) | a checkout of a pinned tag; `BIOAGENT_SKILLS_DIR` / `BIOAGENT_PIPELINES_DIR` point at it |

## The contracts

* **Dependencies point one way.** The platform imports the tools and reads the skills; the tools
  import nothing from the platform (`tests/test_tools_boundary.py`); the skills are files.
* **The tool contract is `bioagent/tools/sdk.py`**: `HarnessTool`, the `ToolContext` protocol, and
  `session_chat_fn` for a bounded call to the session's model (the gateway registers the backend).
* **The platform's doors into the tools** are `sdk`, `catalog` (discovery from `TOOL.md`) and `api`
  (every other name it needs), public names only (`tests/test_repo_boundaries.py`).
* **Adding a tool changes no platform file.** A folder with `TOOL.md` + `tool.py`; the registry, the
  HPC3 routing (`runs_on`), the fast chat (`chat`), the analysis job's dispatcher and the System
  page read the manifest.
* **Import paths stay.** `bioagent` becomes a namespace package: the platform provides
  `bioagent.gateway`, `bioagent.agents`, ...; AiScientist-tools provides `bioagent.tools`. That keeps
  the CLAUDE.md rule (the code namespace stays `bioagent`) and every `python -m bioagent.tools...`
  job entry point, including the ones baked into the images' runscripts.
* **Cross-repository contract tests live in the platform**, which depends on both others:
  `tests/test_tool_contract.py` (the tool names the platform keys logic on, and the ones skills and
  pipelines name, exist), `tests/test_declared_params.py` (pipeline docs state the code's defaults),
  `tests/test_skills_library.py` (skills and pipelines are well-formed).

## Merging the branch while the tools change on main

The split is produced by a program, so main's tool fixes do not have to be ported by hand.
Rehearsed on 2026-09-30 with real new commits on main plus simulated fixes in `run_de`, in the
shared helper `_slug`, in the moved `literature_search.py`, and a new test written against the old
layout: all landed in the right files and the suite passed (2022 tests).

```bash
git checkout claude/aiscientist-architecture-refactor-b0fcaa
git merge main
# The only conflicts to expect are modify/delete ("DU") on the files the branch split
# (scrna_pack.py, scrna_advanced.py, phenotype_dx.py). Keep each one deleted:
git status --short | awk '$1 == "DU" {print $2}' | xargs git rm
# Rebuild the split modules from main's versions and re-point any old import the merge brought in:
python scripts/refactor/split_tools.py --regenerate-from main
python scripts/tool_docs.py
python -m pytest
git commit
```

What each part handles:

* **Files moved whole** (for example `literature_search.py` to `literature_search/tool.py`): git's
  rename detection applies main's edits during the merge.
* **The three split files**: `--regenerate-from main` re-cuts them from main's text, so a fix inside
  `run_de` lands in `run_de/tool.py` and a fix in a shared helper lands in `_lib/scrna.py`. Edits
  the branch needs on top of the generated code are in the script (`GENERATED_EDITS`).
* **Code from main that imports an old module** (a new test doing `from bioagent.tools import
  scrna_pack`): re-pointed to the defining modules.
* **A new module or tool added on main under `tools/`**: the script stops and names it; add it to
  the plan in `split_tools.py` (a move, a split or `STAY`) and give a new tool folder its `TOOL.md`
  (`tests/test_tool_manifests.py` fails until it has one).

## The split itself

Run `python scripts/refactor/extract_repos.py --out <empty dir>` to rehearse at any time; it never
touches this checkout or a remote. The real split follows the same steps.

### P1: AiScientist-skills

1. Create the empty repository RCHENLAB/AiScientist-skills.
2. `extract_repos.py` produces it (`git filter-repo --path skills/ --path preset_pipelines/
   --path-rename preset_pipelines/:pipelines/` plus a README commit). Push it and tag `v0.1.0`.
3. In the platform: delete `skills/` and `preset_pipelines/`; set `BIOAGENT_SKILLS_DIR` and
   `BIOAGENT_PIPELINES_DIR` in the prod `.env` to a checkout of the tag; make `scripts/sync_deploy.sh`
   check out the pinned tag. Induced skills stay in the run-time state directory, not in git.
4. In the skills repository's CI, run the skills checks (`tests/test_skills_library.py` reads the
   configured directories, so the platform's CI runs it against the pinned tag too).

### P2: AiScientist-tools

1. Create RCHENLAB/AiScientist-tools; `extract_repos.py` produces it with `pyproject.toml`
   (distribution `aiscientist-tools`, namespace packaging) and a README. Push, tag `v0.1.0`.
2. In the platform: delete `src/bioagent/tools/`, the moved tests and `src/bioagent/__init__.py`;
   depend on `aiscientist-tools @ git+https://github.com/RCHENLAB/AiScientist-tools@v0.1.0`; make
   the platform's own packaging namespace-aware (setuptools `find_namespace:` under `src`).
3. Uninstall any old editable install of this repository first. Found in the rehearsal: an install
   that still ships `bioagent/__init__.py` is a regular package, and a regular package wins over
   namespace portions, so it silently hides `bioagent.tools` from the new repository.
4. Deploy: the gateway already syncs every portion of `bioagent` to HPC3 (`_pack_bioagent_source`),
   so the job images see the tools without a rebuild. `BIOAGENT_GENESETS_DIR` must point at the
   `.gmt` directory if the tools are installed somewhere other than the synced tree.

### P3: develop under RCHENLAB

* **Decided 2026-09-30:** RCHENLAB/AiScientist stays public and carries everything except
  credentials (database accounts and passwords, API keys, tokens, private keys). Until development
  moves there it is updated as a snapshot with `scripts/publish_public_mirror.py`, which refuses to
  publish anything credential-shaped. A scan of every text change in the history (1,401 commits,
  every branch) found no credential ever committed, so the history-preserving extraction of the tools and skills
  repositories publishes none either.
* Once development happens in public repositories, every push is public: turn on GitHub secret
  scanning with push protection for the RCHENLAB repositories (free for public repositories) and
  keep credentials in the deployment's `.env` and `BIOAGENT_STATE_DIR`, as today.
* CI per repository; CODEOWNERS per work line; the platform's README links the other two; the old
  repository is frozen read-only after the move.
