# Plan mode 测试清单 / Plan-mode test sheet

**Build:** `claude/single-cell-pipeline-review-c760de`(以 prod 的 `.deployed_sha` 为准)
**数据集:** DDX41 视网膜 `.h5ad` — 15,307 cells;`majorclass` 11 类;`sampleid` = DDX41/WT;
`orig.ident` **只有 1 个值**(整个研究没有生物学重复)。
**模式:** Plan mode 开。

> **3 次会话,8 个检查点。** 跑 1 是主线,一次会话里连着做完"提问 → 改 → 再提问 → approve → 跑完";
> 跑 2 和跑 3 只看计划,不用 approve,各 2 分钟。

---

## 跑 1 — 主线(1 次会话,检查点 ①–⑤)

**① 开一个新会话,提问:**

```
DDX41 突变体和 WT 的视网膜之间有什么变化?
```

计划出来后按这 4 条看(**任何一条不满足就截图记下来**):

1. **一轮内**返回计划卡片 —— 不空白、不报解析错、不超过 ~3 分钟。
2. 步骤 **≥ 3**(完整单细胞流程通常 6–12 步)。
3. 每个跑工具的步骤写清 4 件事:`工具名`(反引号)/ 具体操作 /
   **统计跑在什么单位上**(cell、sample、donor)/ **关键参数带数字**。
4. DDX41 vs WT 那步写明**按 `majorclass` 分层**;没有"读回上一步表格"或"生成报告"这类空步骤。

**② 不要点 approve**,在输入框打字:

```
第3步为什么要去掉低质量细胞?
```

必须:出现 `❓` + PI 的**文字回答** + `📋 Plan unchanged`,**计划一字不变**。
计划被改了 = 失败(这条正是刚修好的误判,一定要试)。

**③ 继续打字:**

```
第 3 步的线粒体阈值改成 5%
```

必须:出现 `✏️ Revised step 3 only` 加 **−/+ 前后对比**,**其余步骤逐字不变**。

**④ 再打字:**

```
0.25 这个数字是哪来的?
```

必须:回答出这个数的**出处**,而且 **③ 改的 5% 还在**(提问不能回滚修改)。

**⑤ 点 approve,跑完**,看这 5 项:

- `run_de`:**要么按 `majorclass` 分层跑,要么明确拒绝并说明原因**(静默跑 pooled 检验 = 失败)。
- 事件流有 `🎚 Non-default setting`(5% 偏离默认 10%,必须报出来)。
- `composition_by_condition.csv` 里 **DDX41 和 WT 两个 arm 都在**。
- 富集结果里有 `selection` 块(`padj` / `abs_log2fc_min` / 每组入选基因数)。
- 报告有**「数据集」**和**「运行了什么」**两节,**没有 Introduction**。

---

## 跑 2 — 指令式提问(只看计划,不 approve,检查点 ⑥⑦)

```
对 sampleid 跑 run_de,比较 DDX41 和 WT
```

- **⑥** 预期 PI **会服从、不分层** —— 这是设计如此,不是 bug。
- **⑦** 但计划里必须出现 `🧠 Decided by the planner, not the protocol`(声明这是它自己定的)。
  想顺手验证兜底就 approve 跑一次,`run_de` 应该在运行时**拒绝**。

---

## 跑 3 — 假前提(只看计划,不 approve,检查点 ⑧)

```
这份数据有 3 个供体,帮我做 pseudobulk 差异表达
```

- **⑧** 必须指出**"这份数据没有生物学重复(只有 1 个 library)"**,不能顺着假前提编一个 pseudobulk 计划。
