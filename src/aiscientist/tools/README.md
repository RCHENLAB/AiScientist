# Platform tool support

Scientific execution lives in the standalone `aiscientist-mcp` servers: `cellqc`,
`scrna-analysis`, `scgpt-annotation`, `variant-annotation`, `literature`,
`phenotype-diagnosis` and `data-utilities`. Their released images and reviewed tool schemas are
registered in [`agents/mcp_catalog`](../agents/mcp_catalog/mcp_servers.json), alongside the
existing Atlas service. The gateway bridge binds the actual session, approved inputs and
runtime settings; this directory does not contain the retired scientific implementations.

This file is generated by `scripts/tool_docs.py`. Edit the generator for architecture text;
edit a local extension's `TOOL.md` for its manifest and documentation.

## Optional local manifest extensions

The table, when present, lists only local `TOOL.md` extensions. It is not the scientific MCP
inventory or a statement that a tool has a live executor. Native declarations and runtime
availability are shown separately by the System page and the session roster.

No local manifest-backed tools are currently bundled.

## Retained platform support

- `sdk.py` defines the local tool record and execution context. `catalog.py` retains manifest
  parsing and discovery for local extensions; scientific tools are registered by the MCP bridge.
- `api.py` is the lazy public import boundary for gateway and agent callers. Shared helper
  implementations remain private under `_lib/`: bounded dataset metadata and preflight, Cell
  Ranger layout facts, result export/adoption, report schematics, assembly hints, historical
  parameter metadata and marker-reference checks.
- `datasets.py` is a compatibility forwarding module for metadata helpers. It does not run the
  retired CSV QC or differential-expression fallback.
- `worker_cli.py` runs only metadata `preflight`, `_install_dependency`,
  `_export_result_dataset` and `_adopt_result_dataset` inside the retained platform image.
  `scrna_cli.py` is a thin compatibility entry point for these same operations; neither entry
  point dispatches scientific tools. Generic CodeAct remains in the agent/sandbox layer.
- `run_deps.py` provides the bounded, per-run declared-dependency installer used by the retained
  worker. Scientific MCP images own their scientific environments.

Gene-set libraries are configured as approved compute-side inputs to the scRNA MCP server;
this package no longer bundles a `genesets/` directory. Trusted variant-default panel resolution
lives in [`agents/reference_panels.py`](../agents/reference_panels.py) and its reference data.
Those platform defaults do not reintroduce a scientific tool factory.

## Extending scientific capabilities

Implement scientific algorithms and their tests in the appropriate standalone MCP package.
Publish an immutable image and export its actual tools/list schema, then update the reviewed
MCP registration and matching skill binding through the platform's integration workflow.
Preserve dataset confinement, task identity, result handoff and session/model gates; validate
real service behavior before retiring an existing path. See the
[MCP bridge guide](../../../docs/development/mcp_bridge.md).

## Extending a local platform tool

For an intentionally local extension, retain the SDK/manifest contract:

```
<extension>/
  TOOL.md      front matter = local manifest; body = local documentation
  tool.py      factory returning a HarnessTool
  __init__.py  package documentation
```

Use `aiscientist.tools.sdk` as the execution boundary and keep platform internals out of tool
implementations. Add the manifest fields documented in `catalog.py`, provide generated
parameter/run-location/model-description markers, and run `python scripts/tool_docs.py` and
`python scripts/tool_docs.py --check` with the relevant contract tests. Any required runtime
routing must be implemented and tested explicitly; adding a folder is not an MCP registration
or an automatic HPC scientific execution path.
